# Plano — Prontidão TSE 2026 + Hero 1T com seis termômetros + Identidade das trilhas

> **Errata (2026-09-05, Fase 3).** Este plano cita, em dois pontos, "art. 265 §2º" como base
> normativa para o tratamento de válidos / sub judice / anulados. **Essa citação não se confirmou.**
> Na única fonte disponível (slide oficial do TSE de julho/2026, não o texto integral publicado em
> Diário), o art. 265 tem apenas §1º — liberação do resultado presidencial às 17h — e os §§2º–4º
> pertencem ao art. 267. A obrigação de decompor válidos/anulados/sub judice está confirmada como
> requisito de **schema do EA20** (`v.vvc = v.vv + v.van + v.vansj`), não como artigo da resolução.
> Ver [ADR-0020](../architecture/adrs/0020-conformidade-res-23751-2026.md). Não propagar "art. 265 §2º".

## Context

**Data:** 2026-09-05. 1º turno **04/10** (29 dias), 2º turno **25/10**. Simulados oficiais do TSE em **15–17/09** e **22–24/09** (9h–12h, 14h–17h BRT), ambiente `resultados-sim.tse.jus.br`. Último commit do projeto: 2026-05-18; S07/S08 `planned` com janelas vencidas.

**Por que este plano existe.** A pesquisa TSE de 05/09 derrubou as premissas da documentação de maio: o leiaute **EA20 foi mantido** (JSON, 9 especificações publicadas), **não existe cadastro prévio**, a norma vigente é a **Res. TSE 23.751/2026 arts. 264–269** (267 §4º veda alterar conteúdo dos dados; 265 §2º pede válidos/sub judice/anulados), e há limites operacionais duros: **100 req/s por IP → bloqueio 10 min; 304 conta; sem arquivos de índice (EA14/EA15 direcionam ao EA20); 404 malformado pode bloquear IP; sem freeze de leiaute**. `resultados.tse.jus.br/oficial/comum/config/ele-c.json` ainda está em `ele2024` — códigos de eleição 2026 não existem.

Ao mesmo tempo o usuário definiu dois conceitos de produto: **interface distinta por turno** (2T intocado; 1T com **seis termômetros de projeção**: 1º, 2º, 3º, outros, brancos/nulos, abstenção) e **identidade visual distinta entre a trilha presidencial (nacional → UF → município) e a de governador (UF → município)**.

**Bugs confirmados que bloqueiam tudo:**
1. `lib/tse/ea20-schema.ts:97` — `f: z.literal("o")` + `.strict()` rejeita o simulado; `tests/unit/tse/ea20-schema.test.ts:54` *protege* o bug.
2. `lib/tse/targets.ts:68` — host `https://resultados.tse.jus.br/oficial/` hardcoded.
3. `api/model/project.py:625` (`_extract_zone_candidate_pcts`) e `:551` (`fetch_municipio_aggregates`) leem `payload.get("cand")` no topo; o ingest grava o envelope `{dg,hg,f,cdabr,abr:[{…cand}]}` → em produção retorna `{}` e a zona some do swing. Testes usam payload achatado.
4. Escala: `compute_uf_projections`/`compute_national` emitem fração [0,1]; `build_edge_payload:1799-1811` copia direto (UI só funciona com fixture 0–100); `:1878` `top_pct < 50.0` é sempre verdadeiro → todo governador "vai a 2T"; `build_uf_payloads:1568` divide por 100.
5. `lib/tse/client.ts` — sem rate limiter de saída (só `CONCURRENCY=20`), 429 não retryado (`retry.ts` só ≥500), sem `Accept`, User-Agent declara cadastro inexistente.

**Bloqueio externo:** PDFs dos 9 leiautes atrás de WAF (curl/WebFetch 403; navegador abre save dialog). O usuário precisa baixá-los para o diff campo-a-campo de EA20/EA14/EA15.

## Fase 1a — Modelo: participação (regra de três) + "Outros" com IC + payload (08/09 → 12/09)

**Pronto quando:** `pytest` verde incluindo reprodutibilidade; `_do_project` com envelope real emite `participacao` nacional e por UF em 0–100; `writeProjection` sem warn de tamanho.

### 1a.1 `api/model/turnout.py` (novo)
```python
class ZonaParticipacao(TypedDict): cod_zona:int; weight:int; aptos:int; comparecimento:int; abstencao:int; brancos:int; nulos:int; validos:int; psa:float
class ParticipacaoEstimate(TypedDict): pct_atual:float|None; pct_projetado:float; lower:float; upper:float; n_zonas:int; num:int; den:int; estimates:np.ndarray  # pct em 0–100; estimates em fração
Metric = Literal["abstencao","brancos_nulos"]
def metric_value(z, metric) -> float            # abstencao/aptos ; (brancos+nulos)/comparecimento
def estimate_uf_participacao(zonas, metric, pct_apurado_uf, seed, n_resamples=1000) -> ParticipacaoEstimate
def aggregate_national_participacao(by_uf, eleitorado_total_by_uf) -> ParticipacaoEstimate
```
Algoritmo (regra de três, D5): filtrar zonas com `aptos > 0`; `pct_atual = Σnum/Σden` das zonas apuradas (razão literal); ponto projetado = média de `metric_value` ponderada por `weight` (aptos 2026) — i.e., a taxa observada extrapolada ao total; IC = bootstrap de zonas idêntico a `bootstrap.py` (`default_rng(seed)`, seed derivado como em `compute_uf_projections:783`); se `pct_apurado_uf < 5` → `inflate_ci_low_apurado` (`edge_cases.py:46`); se 0 zonas → `pct_projetado = None`-equivalente (omitir métrica; UI mostra "aguardando"). Clip [0,1], retorno em 0–100. Nacional: soma ponderada por aptos como `aggregate_national_estimates:1020`; `pct_atual` nacional = razão das somas.

### 1a.2 "Outros" com IC (`project.py`)
`compute_outros_estimates(estimates, rank_by_cand, min_rank=4) -> (np.ndarray, n_candidatos)`. Nacional: em `compute_national` após `rank_by_cand` (`:1170`) — devolver via 5º elemento `extras` do tuple (atualizar `replay_batch.py` para `*_`). Por UF: em `build_uf_payloads` com novo parâmetro `estimates_by_uf=None`. `pct_atual` de outros = soma dos `pct_atual` rank ≥ 4 (preencher `pct_atual` nacional a partir de `municipio_aggregates`, hoje `0.0` em `:1808` — pré-requisito do marcador "apurado").

### 1a.3 Fiação e payload
`compute_participacao(cargo, turno, seed_base, snapshots, eleitorado) -> (by_uf, nacional)`; `build_edge_payload(..., participacao_nacional=None, outros_nacional=None)`, `build_uf_payloads(..., estimates_by_uf=None, participacao_by_uf=None)` emitem:

```json
"participacao": {
  "abstencao":     {"pct_atual": 20.1, "pct_projetado": 21.4, "lower": 19.8, "upper": 23.0, "base": "aptos"},
  "brancos_nulos": {"pct_atual": 6.9,  "pct_projetado": 7.3,  "lower": 6.6,  "upper": 8.1,  "base": "comparecimento"},
  "outros":        {"pct_atual": 5.2,  "pct_projetado": 5.0,  "lower": 4.1,  "upper": 6.2,  "base": "validos", "n_candidatos": 8},

```
Omitir métrica/chave quando não calculável. **Não persistir** em `projections` (`candidato_id NOT NULL`); registrar em spec 002 RF-020.1 como "persistência deferida". Sem migration nesta fase.
