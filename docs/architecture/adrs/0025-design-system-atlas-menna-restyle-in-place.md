# ADR-0025 — Adoção do design system Atlas Menna por restyle-in-place, não árvore v2 paralela

## Status

Aceito.

## Contexto

Em 2026-09-07 o usuário aprovou um kit de design ("Atlas Menna", exportado do Claude Design em `docs/design-system/atlas-menna/`) para substituir a linguagem visual atual do produto, e decidiu rodá-lo já no simulado oficial do TSE de 15–17/09 — ou seja, direto na branch `s07/simulado-ready-hero-1t`, sem uma janela de estabilização dedicada. O kit traz uma paleta paper/ink com accent ocre, escala tipográfica própria (10–64px), 17 componentes de referência (`components/`) e um protótipo (`ui_kits/atlas-menna/`), mas não é um pacote instalável: é um export estático, com CSS solto e JSX de referência que não compartilha nada do build atual.

O estado real do código impõe restrições que o kit, sozinho, não conhece. `app/globals.css:1` é só `@import "tailwindcss"` — Tailwind **v4** via `@tailwindcss/postcss`, sem `@theme`/`@config` — o que significa que `tailwind.config.ts` (escrito no formato v3, com `theme.extend`) **nunca é carregado**: classes como `max-w-container` e `bg-bg-muted` não emitem CSS algum hoje, e a escala `text-xs`..`text-4xl` usada em ~178 lugares vem da escala default do Tailwind v4, não dos 12→48px que `docs/design-system/tokens.md` afirma existir. A estilização de dado é mista: ~335 `className` e 47 arquivos com `style={{ ...var(--color-*) }}`, sendo que `lib/utils/cand-color.ts` lê tokens de cor via `getComputedStyle` para alimentar o MapLibre em hex — qualquer token que exista só como classe Tailwind não-emitida é invisível para esse caminho. Há 46 componentes com 42 testes unitários que importam por nome de arquivo/export, e 4 páginas (`/`, `/uf/[sigla]`, `/governador`, `/uf/[sigla]/governador`) cujo shell hoje é só `components/layout/RaceHeader.tsx` — `app/layout.tsx` não tem header/nav global, apenas `{children}`, e o atributo `main[data-trilha]` (ADR-0019) mais o `<Footer>` de cada página são testados como filhos do `<main>` nos testes de integração (`tests/integration/*-page.test.tsx`, `tests/unit/pages/UFPage.test.tsx`). 54 páginas de UF são hoje pré-renderizadas estaticamente; o carry-over recente do `BaseToggle` já mostrou que ler `cookies()` ou `searchParams` no layout as tornaria dinâmicas sem necessidade.

Duas alternativas foram avaliadas. A primeira — construir uma árvore paralela `components/v2` + rotas `app/v2`, com cutover para depois do 1º turno — isola o risco de regressão visual do simulado, mas custa 25–30% a mais em superfície (dois conjuntos de componentes, dois conjuntos de testes, um merge de cutover sob pressão). Esse custo só se paga se o cutover for tardio o bastante para justificar a duplicação; como a decisão do usuário é entregar a UI nova **já no simulado 1** (15–17/09), a duplicação nunca amortiza — o produto ganharia uma segunda árvore para descartar em poucos dias. A segunda alternativa é o restyle-in-place: portar a linguagem visual do kit para os arquivos existentes, preservando nomes de export e props, com o shell global entrando como camada aditiva. É mais arriscada no curto prazo (qualquer erro de token quebra a UI que vai para o simulado), mas não gera dívida de dois sistemas coexistindo.

## Decisão

O AtlasMenna adota o design system Atlas Menna por **restyle-in-place**, direto na branch `s07/simulado-ready-hero-1t`, ao invés de árvore `v2` paralela com cutover posterior.

1. **Mesmos arquivos, mesmos exports.** Os 46 componentes existentes são restilizados nos próprios arquivos, mantendo nome de export e assinatura de props — os 42 testes unitários que importam por nome continuam válidos sem alteração de import. Onde o kit Atlas Menna introduz um componente sem equivalente direto (ex.: `TopBar`, `TabBar`, `HoverCard`, `Sheet`, `SegmentedControl`), ele entra como **componente novo**; nunca como rename de um componente existente que cumpre outro papel. `Footer` e `main[data-trilha]` (ADR-0019) permanecem de posse de cada página — não migram para o shell global.
2. **Shell global aditivo.** `TopBar` e `TabBar` (portados de `docs/design-system/atlas-menna/components/layout/`) passam a renderizar em `app/layout.tsx`, acima de `{children}`. Isso não estende o layout para ler estado dinâmico (cookies, searchParams) — o toggle de tema e a navegação de abas continuam client-side, sem tocar a pré-renderização estática das 54 páginas de UF.
3. **Tokens em Tailwind v4 `@theme static`, fonte única.** `app/globals.css` passa a declarar os tokens do kit dentro de um bloco `@theme static { ... }` (não `@theme` puro): sem `static`, o Tailwind v4 tree-shaka variáveis que não aparecem em nenhuma classe utilitária do bundle, e `lib/utils/cand-color.ts` perderia as cores que só lê via `getComputedStyle` para o MapLibre. Três camadas: (a) primitivos do kit — paper/ink, accent ocre, status, `--party-*`, escala tipográfica 10–64px, spacing, radius, shadow, motion, `--container-page: 1280px`; (b) os tokens semânticos já em uso hoje são preservados com os mesmos nomes (`--color-bg`, `--color-text`, `--color-border`, `--color-part-*`, `--color-band-*`, status), agora resolvidos a partir dos primitivos do kit; (c) cascata de `main[data-trilha]` (`--trilha-accent`/`--trilha-accent-soft`) permanece em `:root`/seletor de atributo puro, fora do bloco `@theme`, porque não é um token de tema global — é uma redefinição condicional por página. `tailwind.config.ts` é **removido** do repositório: era morto desde a migração para v4 e sua presença induzia a acreditar que `theme.extend` fazia algo. Cor ligada a dado (candidato, partido, participação) continua em `style` inline com `var(--color-*)`; cromo de UI (fundo, borda, texto neutro) migra para classes Tailwind geradas a partir do `@theme`. Os tokens lidos pelo MapLibre continuam expressos em hex (MapLibre não aceita `var()`).
4. **Fontes via `next/font/google`**: Spectral 400/600 para display, Archivo 400/500/600 para corpo, JetBrains Mono 400/500 para números — todas `subsets: ["latin"]`, `display: "swap"`, substituindo Inter/Source Serif 4 em `app/layout.tsx`. As variáveis que o `next/font` gera são renomeadas para `--font-serif-display-src`, `--font-sans-src`, `--font-mono-src` (não os nomes finais `--font-serif-display`/`--font-sans`/`--font-mono`) e mapeadas para os nomes finais dentro de um `@theme inline { ... }` — isso evita colisão entre a variável que o `@theme` do Tailwind v4 quer declarar e a classe que `next/font` já injeta no `<html>`.
5. **Dark mode via `data-theme` no `<html>`.** Um toggle client (`ThemeToggle`, do kit) grava a preferência em `localStorage`; um script inline no `<head>` lê `localStorage` antes da hidratação para aplicar `data-theme="dark"` sem flash. Deliberadamente **não** usa cookie nem `searchParams` — qualquer uma das duas exigiria ler estado por requisição no layout ou nas páginas de UF, tornando dinâmicas as 54 páginas hoje estáticas (o mesmo problema já observado com o `BaseToggle`). Default é claro; todo token do kit tem par claro/escuro medido antes de ir ao ar (o próprio `tokens/colors.css` do kit já traz o bloco `[data-theme="dark"]` como base).
6. **RSC por padrão.** `"use client"` fica restrito a toggles (tema, abas), `Sheet`, `HoverCard`, mapas e busca. Estado de cargo/turno continua vivendo nas rotas (`/`, `/governador`, `/uf/[sigla]`, `/uf/[sigla]/governador`), não em contexto client global.
7. **Mapa inalterado em arquitetura.** MapLibre + PMTiles (ADR-0003/ADR-0004) e o carregamento via `next/dynamic({ ssr: false })` (ADR-0010) continuam exatamente como estão. Só a linguagem visual é portada: 5 degraus de intensidade por margem (`--party-pt-1..5`/`--party-pl-1..5` do kit, mapeados nos tokens semânticos existentes, não substituindo ADR-0013), traço de contorno cor de papel (`--map-stroke`), rótulos em mono, o token `--map-uncounted` para município sem apuração, e o hover card ao passar o mouse. `assets/geo/` do kit (TopoJSON, 1.2MB) não entra no repositório — geometria continua exclusivamente via pipeline PMTiles.
8. **Remoção de dependências mortas.** `framer-motion` e `d3-array`/`d3-scale`/`d3-shape` saem do `package.json` — nenhum import real existe hoje, só comentários. Movimento (`am-pulse`, `am-fade`, `am-rise`, inspirados em `--ease-out`/`--dur-*` do kit) passa a ser CSS puro, sob o mesmo kill-switch `prefers-reduced-motion: reduce` já presente em `app/globals.css:215`.

Paleta por partido (cores exatas de `--party-pt-*`/`--party-pl-*`/`--party-*` de terceiros e sua relação com `--color-cand-*`/ADR-0013) é registrada separadamente em ADR-0024, escrito em paralelo — este ADR trata do **mecanismo** de adoção do kit (arquivos, camadas de token, shell, fontes, tema, dependências), não da paleta em si.

## Consequências

**Positivas**:
- Nenhuma duplicação de árvore: os 42 testes de componente e os testes de página (`tests/integration/*-page.test.tsx`, `tests/unit/pages/UFPage.test.tsx`) continuam válidos porque imports e estrutura DOM (`main[data-trilha]`, `Footer` dentro do `<main>`) não mudam de lugar.
- `tailwind.config.ts` morto é removido, eliminando uma fonte de confusão real (classes que pareciam funcionar e nunca emitiram CSS).
- `@theme static` corrige a lacuna de hoje: tokens deixam de existir só como comentário em `tokens.md` e passam a estar de fato disponíveis tanto via classe Tailwind quanto via `getComputedStyle` para o MapLibre.
- Home e página de governador ganham `--container-page: 1280px` como largura máxima real (hoje só documentada, não aplicada, porque `max-w-container` não emitia nada).
- Remoção de `framer-motion` e `d3-*` reduz peso potencial de bundle sem perder nenhuma funcionalidade em uso (RNF-007a segue com zero folga acima da dobra: 148,7 KiB de framework hoje já consome quase todo o orçamento de 150KB, então toda dependência morta removida é orçamento recuperado, não gasto).
- Dark mode fica pronto usando o par de tokens que o próprio kit já trouxe medido, em vez de o time ter que inventar uma segunda paleta do zero.

**Negativas**:
- A escala tipográfica do kit (10–64px, `--text-2xs`..`--text-5xl`) substitui a escala default do Tailwind v4 hoje usada em ~178 ocorrências de `text-xs`..`text-4xl` no código — todas precisam ser revisitadas visualmente, porque os nomes das classes Tailwind se mantêm mas os valores em px por trás mudam.
- Restyle-in-place na própria branch do simulado significa que um erro de token (contraste, cor invertida, escala) vai para produção na janela crítica de 15–17/09 sem uma branch de fallback separada — a mitigação é fatiar o trabalho em blocos que ficam verdes (build + testes) a cada commit, e congelar mudanças de UI durante as janelas do simulado propriamente ditas (15–17/09 e 22–24/09), com rollback via revert do deploy na Vercel e `git revert` caso algo passe.
- 13 testes de cor (afetados por ADR-0024, em paralelo) e as medições de contraste WCAG existentes em `tokens.md` precisam ser refeitas; com dark mode, o número de combinações a medir (claro + escuro, por token) dobra em relação ao que `a11y-perf-auditor` já validava.
- `@theme static` força todo primitivo do kit a existir no CSS final mesmo que nenhuma classe o use hoje — é o oposto do comportamento de tree-shaking que o Tailwind v4 oferece por padrão; o ganho de correção (MapLibre não perde cor) tem esse custo de bytes, que precisa ser medido pelo `a11y-perf-auditor` contra RNF-007a.
- `--trilha-accent`/`--trilha-accent-soft` (ADR-0019) continuam fora do `@theme`, em `:root`/seletor de atributo — dois mecanismos de token coexistindo (`@theme static` para o tema global, cascata pura para trilha) é uma segunda fonte de "onde declaro isso" que precisa ficar documentada, sob risco de um desenvolvedor futuro tentar mover a trilha para dentro do `@theme` e quebrar a redefinição condicional por `data-trilha`.
- A rejeição da árvore `v2` paralela significa que não há ambiente de comparação lado a lado antes do simulado — qualquer regressão visual só é percebida em preview/produção, não em uma versão anterior ainda no ar.
